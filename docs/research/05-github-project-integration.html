What Can Safely Move Into The Public Repo

Public-safe material:

  • The category framing: SMS-first family coordination assistant.
  • The core wedge: trusted closed-loop execution for overloaded parents and caregivers.
  • Transcript-refined framing: parent assistant / task execution intervention, not family calendar or spouse-nudging software.
  • The product boundary: saved contacts first, not a marketplace or broad discovery product.
  • Public competitor landscape at a high level.
  • Defensibility themes: trust, consent, permissioned contact graph, reliability, privacy posture, workflow templates, and distribution.
  • Public pricing hypotheses, clearly labeled as hypotheses.
  • Pilot success metrics:
  • completed requests
  • time to first option
  • time to confirmed booking
  • parent manual-intervention rate
  • failed/abandoned task rate
  • cost per completed coordination
  • willingness to pay after trial
  • Public-safe strategic questions with names/contact details removed.

What Should Stay Private

Keep out of the public repo unless explicitly approved:

  • Private Outlook/Gmail evidence and any direct email-derived wording.
  • Raw transcript text, private meeting notes, or non-public founder/partnership discussion.
  • Email addresses, phone numbers, private scheduling details, and forwarded-message context.
  • Internal Utlyze / SolutionStream positioning and partnership economics.
  • Named IP, contribution, equity, or credit questions involving specific people.
  • Claims about Tamara's private reach or distribution list unless she confirms the exact claim can be public.
  • Any live deployment URLs, admin URLs, secrets, customer/test-family data, or vendor-account status.
  • Any healthcare/special-needs details that could imply sensitive family or medical context.

3. docs/recommended-architecture.md

Use only for architecture implications from the research:

  • Keep "coordination core + adapters" as the technical center.
  • Keep healthcare scheduling and voice agents behind stricter compliance and privacy gates.
  • Add observability and measurement requirements if the repo moves from prototype to pilot.

Avoid mixing GTM, pricing, and partnership strategy into this file.

4. README.md

Use only as an index:

  • Add one short link to the public-safe strategy document.
  • Do not put the detailed research directly in the README.

5. docs/index.html

Only update this after the markdown strategy doc is stable. Since this is published through GitHub Pages, it should contain the most conservative public-safe version of the research.
