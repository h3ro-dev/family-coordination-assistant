AI-Native Roadmap Pricing Architecture

Date: 2026-05-12 Trace ID: trc_20260512_013908Z_sxh8i9wk

Executive Update

The pricing architecture should be tied directly to the roadmap. The proposal should not ask Tamara to evaluate a generic 6-8 week "project cost" without seeing exactly what is built, what is tested, and what decisions are produced.

The previous market-validation pass was directionally useful but over-weighted traditional agency replacement cost. That was too high for the first sprint if we assume:

  • The February family-coordination-assistant repo is a usable starting point.
  • The sprint is deliberately narrow.
  • We use AI-assisted development aggressively.
  • We do not include native mobile apps, full provider voice, full HIPAA / SOC 2, deep OAuth, 24/7 support, or broad enterprise systems in the first 6-8 weeks.

The revised pricing should separate:

  1. AI-native 6-8 week Build + Test Sprint: lower cash, tight roadmap, explicit tests.
  2. Phase 2 product expansion: additional connectors, parent voice, richer admin, sponsored cohort readiness.
  3. Phase 3 voice / provider / enterprise scale: higher-risk voice, compliance, reporting, and scale work.

Revised Recommendation

Option B remains recommended, but the proposal should shift from a broad $50K-$90K sprint to a narrower AI-native first sprint:

  • Option A: Cash Services / No Equity: $40K-$70K for the 6-8 week AI-native sprint, 0% equity.
  • Option B: Strategic Build Partner: $25K-$45K for the sprint, $8K-$16K/month if continued, and 4%-8% equity or warrants that vest over milestones.
  • Option C: Studio / Cofounder-Level Partner: $0-$20K/month during active build plus 12%-25% earned equity, only if Utlyze / SolutionStream is carrying sustained product, engineering, GTM, and operating responsibility.

These numbers assume the first sprint is a focused roadmap sprint, not a full platform build.

What The 6-8 Week Sprint Includes

Phase 0: Audit And Roadmap Lock

Timing: days 1-3.

Build / create:

  • Repo, deployment, vendor-account, and ownership map.
  • Current-state technical risk list.
  • Sprint backlog with must-have / should-have / later split.
  • Phase gate table for voice, healthcare-adjacent tasks, and data retention.

Test / verify:

  • Production URL and deployment state.
  • SMS/email loop status.
  • Twilio webhook and voice job baseline.
  • Database/schema and job queue readiness.
  • Account ownership and credential handoff path.

Decision:

  • Confirm whether the repo is usable for the AI-native price.
  • Confirm final sprint scope and any scope that moves to Phase 2.

Phase 1: Core Coordination Hardening

Timing: weeks 1-2.

Build:

  • Saved-contact task model and status states.
  • Twilio signature verification.
  • Basic rate limiting / abuse checks.
  • Task event ledger.
  • COGS tracking by task and channel.
  • Admin visibility for task state, failed/blocked tasks, and completion.

Test:

  • End-to-end babysitter / caregiver coordination loop.
  • Failed reply, no reply, ambiguous reply, duplicate reply, and opt-out handling.
  • SMS/email cost capture.
  • Basic security / webhook verification.

Decision:

  • Is the first coordination loop reliable enough for a paid pilot?

Phase 2: Autonomous Onboarding And Paid Pilot Path

Timing: weeks 3-4.

Build:

  • Autonomous household setup.
  • Trusted-contact import / manual entry path.
  • Consent and task-scope setup.
  • Stripe checkout or payment-request path.
  • Plan limits / task credits.
  • First-task guided flow.

Test:

  • 5-8 internal / friendly users complete setup without staff onboarding.
  • Payment friction.
  • First-task submission quality.
  • Blocked-task and parent-handoff logic.

Decision:

  • Is self-serve setup credible without a human onboarding option?

Phase 3: Pilot Instrumentation And Launch

Timing: weeks 5-6.

Build:

  • Pilot dashboard for activation, first task, repeat task, completion, COGS, containment, and blocked tasks.
  • Pilot invite and offer-card flow.
  • Post-task feedback form.
  • Refund / extension rule.
  • Sponsor-proof evidence template.

Test:

  • 18-24 family pilot activation.
  • Paid checkout or paid commitment.
  • Completion rate by task type.
  • Cost per completed task.
  • Repeat usage and reported relief.

Decision:

  • Scale, pause, narrow, or pivot the first task loop.

Phase 4: Voice And Next-Phase Decision Package

Timing: weeks 7-8.

Build:

  • Parent-facing voice intake prototype or script.
  • Low-risk outbound voice policy matrix.
  • Voice provider recommendation.
  • Counsel-review packet for high-risk workflows.
  • Phase 2 roadmap and budget.

Test:

  • Parent-facing voice intake on low-risk requests.
  • Scripted nonclinical outbound calls only if product gates are met.
  • Structured-result retention without raw transcript/audio by default.

Decision:

  • Whether voice should move into Phase 2, stay parent-facing only, or wait.

What Is Not Included In The First Sprint

  • Native iOS / Android apps.
  • Full realtime voice bridge.
  • Full provider / healthcare scheduling at scale.
  • Insurance, prior authorization, billing, or clinical workflows.
  • Full HIPAA / SOC 2 program.
  • Deep calendar/contact OAuth beyond the pilot path.
  • 24/7 support or human concierge operations.
  • Enterprise sponsor reporting beyond the pilot evidence template.
  • Fundraising, legal formation, or legal document drafting.
